# 工程消费接口说明

工程读取只从 `canonical/index.json` 开始：校验版本与状态，按 artifacts 的语义名称选择文件，再校验字节数、SHA-256 和对应 Schema。禁止依赖 Raw 文件编号、固定采集日期、旧 snapshot 或 README 中的路径说明。

| 任务 | 读取 artifacts |
|---|---|
| 页面布局/实例 | page-structure、design-identity |
| 组件身份/合同 | design-identity、components |
| Variant 原生 key | component-variants |
| Token 绑定与值 | variables-used、必要时 variable-collections |
| 审计定位 | provenance，再由审计工具显式读取 Raw Manifest |

Button 当前转换器按需读取 components、component-variants、page-structure、variables-used、provenance 五项。其他三项不用加载。代码位于 MappingWorkbench/mapping/design/pixso_button.py；它不导入 capture，不读取 sourceManifest 或 archive。

## Button 评审与生成

以下命令从 `Source/Qt/MappingWorkbench/mapping/design` 执行。index 与 rule 为唯一设计/映射输入；output 必须为新文件。

```powershell
python -B pixso_button.py ../../../../DesignEvidence/packages/DesignTest-2-145/canonical/index.json pixso-button/rule.json <review-snapshot.json> --inspect
# 检查生成的紧凑证据；SHA-256 为 inspect 打印的 sha256。
python -B pixso_button.py ../../../../DesignEvidence/packages/DesignTest-2-145/canonical/index.json pixso-button/rule.json <button.ui-contract.json> --reviewed-sha256 <已检查证据的SHA256>
```

inspect 只导出紧凑证据，不标记 reviewed。正式输出含 UI contract 与 design-tree；契约保留原 Button 属性组合门禁，新增组件不会自动获得 Qt 映射。

source.kind=pixsoCanonical；snapshotSha256 是紧凑 Canonical 证据快照哈希，不是 Pixso 原始响应哈希。canonicalIndexSha256 绑定完整入口字节；snapshotBase64 包含所选身份、结构、七条绑定、七个变量的模式/Alias及相应来源链，不包含全量 Raw、tools/list 正文或历史证据。

design 使用 variantNodeId/componentSetId/nativeComponentKey/mappingKey/libraryVersion/alias。当前示例是 Variant 展示，不填写 instanceNodeId。实际页面实例的身份从 design-identity.instances 独立取得；缺少 mainComponent 的实例保持未知引用。

Qt 仅验证已生成的紧凑工程合同及其显式评审哈希，不连接 Pixso、不读取 Raw。Schema 通过或 verify 通过不代表人工评审通过。Figma 使用既有 figmaNormalized 来源，保持独立。

## 失败规则

版本不支持、artifact 缺失/越界、哈希变化、身份漂移、未登记属性组合、证据评审哈希不匹配时明确失败。没有新旧输入自动 fallback；需要补证时进入显式审计/复采流程。

采集使用 tools/capture.py；归一化使用 tools/normalize.py；审计使用 tools/verify.py。工程只依赖 contract_io 的合同读取，不依赖采集过程。
