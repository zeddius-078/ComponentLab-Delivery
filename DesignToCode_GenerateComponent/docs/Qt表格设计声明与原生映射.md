# Qt 表格组件样式、Token 与应用合同

更新日期：2026-10-03。

**本文件属于 Gen_comp，回答“平台表格如何获得统一样式、状态和可公开配置的原生能力，并供业务使用”。它不负责读取设计页面、生成业务页面或定义交付目录。**

已确认基线：沿用 Qt5 Widgets 表格能力，优先复用已有 Z_TableView；基础能力先建立可验证合同，高级能力逐项扩展。下文的待建设项与工程建议不是已完成的实现。

配套文档：[Gen_layout：表格设计读取、Qt 页面生成与业务工程接入](../../DesignToCode_GenerateLayout/docs/Qt表格设计声明与原生映射.md)。九类完整设计声明和交付转换规则在那里维护。本文件不再复制该清单，也不是其同步副本。保留现有文件路径，避免原链接失效。

## 0. 本轮组件试点验证合同

**本轮验证选定场景下的组件样式与接入方法，不预先承诺形成通用、稳定的表格产品。** 创新探索允许得出“方案尚不成立”或“只有部分条件可用”的结论，但输入、过程、失败证据和后续处理必须清楚。

### 0.1 规划定位与范围来源

参照 [试点规划 v4.6](Orders-Design-System-协同排期/README.md)：设计表格族标准化对应 M2-14，Token 与样式应用对应 M3-13，组件接入对应 M3-15。本文件只展开 C++ Qt 表格相关部分，不替代整个 PyQt/Vue2/C++ Qt 计划，也不另设承诺日期。

该规划保留旧日期及部分历史规则。本轮采用用户最新确认的业务自由度：业务可以覆盖和手改自己接收的文件；平台默认样式和生成基线仍按 Source 维护。总规划版本同步尚待处理，本轮不据此宣称所有规划文本已经统一。

具体业务页面、设计版本、列、状态、Profile、数据规模与测试环境，统一引用 [Gen_layout 第 0 节](../../DesignToCode_GenerateLayout/docs/Qt表格设计声明与原生映射.md)。Profile 已确定为 light-compact（亮色紧凑），其余范围信息仍待固定；可以先做组件探针，但不能将探针或 Demo 标为真实业务试点完成。

### 0.2 同一表格族的两种模式

| 模式 | 本轮最小组件验证 | 验证边界 |
| --- | --- | --- |
| 数据浏览 | 表头、正文、明确尺寸、正常/选中/禁用等选定状态，以及选择和排序接入 | 不默认实现完整筛选、分页、冻结或远程查询 |
| 可编辑 | 复用上述结构，验证一类基础编辑器、进入/退出编辑、值变更和只读限制；接收外部校验/提交反馈的最小方式 | 真实校验规则、数据提交与权限由业务实现，不在组件内编写业务系统 |

具体编辑类型和反馈呈现需在选定场景后固定，不先创造复杂错误提示体系。两种模式共享组件与样式来源，不能拆成两套独立表格，也不能只测浏览就称两种模式完成。

下文的部件、状态和原生能力是检查目录，不是要求首轮全部实现。多级表头、冻结、合并、复合单元格等默认暂缓；确属场景必需时先调整范围，不静默降级，也不暗中扩大实施。

### 0.3 可控的是试验，不是预先保证的结果

每次只验证明确的样式、状态或接入假设，固定输入与环境，记录预期、观察、证据、修正及复查。使用既有组件报告或试点记录，不新增审批体系、等级矩阵或另一套任务表。

结果标为“未验证”“已观察”或“已复查”。一次截图或一次启动只支持对应观察；按相同条件重放并检查通过后才记为已复查，不外推为所有数据量、Profile、设备和业务都稳定。

允许保留范围外问题；影响选定路径的问题未解决时，记录当前卡点，不能宣称该目标完成。没有证据的能力、不正确的 Token 引用、静默丢样式等问题不因创新属性而视为可接受的成功结果。

## 2. 表格样式应按哪些部件建设

以下是待补齐的设计检查目录，不是宣布已有的 Token 路径，也不是首轮全量开发清单。按第 0 节所选两种模式勾定实际需要的部件与状态，其余标为暂缓或不适用。UCD 提供视觉依据和 Token 绑定，平台核对现有定义、消除重复后确定正式路径。

| 部件 | 需要明确的样式 | 应覆盖的状态或边界 |
| --- | --- | --- |
| 表格整体 | 表面色、文字、外边框、圆角 | 正常、禁用；外边框圆角不自动证明所有子区域正确裁剪 |
| 表头区 | 背景、文字、字体、边线、内容留白、排序图标 | 正常、排序、必要的交互反馈 |
| 正文单元格 | 字体、文字、背景、对齐、内边距需求 | 正常、禁用、长文本和空值 |
| 行列分隔与交替行 | 网格线、交替背景及启用规则 | 与选中态重叠时的效果 |
| 选择与焦点 | 选中文字、背景、焦点提示 | 活动/非活动窗口、键盘焦点、选择与悬停重叠 |
| 复选指示器 | 尺寸、图形、勾选与部分选中呈现 | 勾选、未勾选、禁用；与选中行区别 |
| 编辑器 | 编辑控件样式、错误提示需要 | 编辑、禁用；业务校验结果由业务提供 |
| 滚动条与边角 | 滚动条部件、表头交角区域 | 优先复用平台已有样式，不新建重复体系 |
| 复合单元格 | 状态胶囊、多个动作、头像与多行信息 | 单独定义部件、数据和动作合同 |

没有批准的值就保留待设计项，不填临时灰色或凭经验制造 Token。需要某种交互状态时，应明确触发条件，不能只定义一张状态效果图。

## 3. Token 应用链与生成边界

目标链路为：

```text
已批准的 Token Source
→ 解析 Alias 与所选 Profile
→ 表格部件和状态的使用映射
→ QSS 最终值 + 原生配置值 + 委托需要的显示值
→ Z_TableView / QHeaderView / 单元格显示
→ 组件独立验证与 SDK 发布
```

这仍然是编译后的样式应用，不是给 QSS 添加运行时变量系统。模板可以含占位符，但发布的 QSS 必须完成解析。

现有生成工具会重建原生 .h/.cpp 和 .qss.in。后续如补充表格专属能力，必须先明确它由生成输入、模板生成逻辑还是受保护的专用实现维护，不能只手改一次输出文件。此处仅记录实现风险，不在本轮修改生成机制。

建议的映射记录至少说明“设计部件/状态 → 已批准 Token → 值类型 → QSS/原生 API/委托消费端”。这是配置合同，不是新的 Token 层，也不另建第二份原始色板。

Theme 与 Density 保持独立：颜色与状态取当前主题，尺寸与间距取密度规则。不能仅检查 QSS 色值变化，而忽略行高、图标和自定义单元格仍停留在另一套配置。

未绑定 Token 但明确且符合规范的页面值，Gen_layout 可以按既定规则生成并记录设计补全项。Gen_comp 不将每个页面特例自动升级为公共 Token；公共默认值缺口由 UCD 与平台共同补齐。

允许这些值用于探索，不等于设计标准化通过。纳入本轮首批标准化范围的稳定视觉属性仍需完成 Token 绑定与复查；没有完成时如实保留状态，不计作已达标。范围外缺口留待后续，不要求当前试点补齐所有表格属性。

## 4. QSS、原生 API 与委托分别承担什么

以下为基于 Qt 原生机制的应用方向，具体选择器及效果仍需在项目 Qt 5.15.2 与实际 SDK 上验证。

| 需求 | 首选应用位置 | 不能混淆的边界 |
| --- | --- | --- |
| 表格文字、表面、边框 | 表格范围的 QSS | 不把每页特例写入全局无范围规则 |
| 表头外观与排序箭头 | QHeaderView 的 section、up-arrow/down-arrow 样式 | 表头文字仍来自模型 headerData，不生成独立 Label |
| 选中颜色、交替背景、网格线色 | QSS 对应属性 | 交替行、网格显示等行为还需要原生开关 |
| 列宽模式、行高、列隐藏与移动 | QHeaderView / QTableView 公开 API | 不是 CSS 布局，不用 QSS 模拟任意比例列宽 |
| 普通单元格文字、图标、复选与对齐 | 模型数据角色及默认委托 | 行为和数据来源不能从 QSS 推导 |
| 胶囊、复合内容、特殊编辑器 | 平台明确提供的 QStyledItemDelegate 扩展 | 不等于重新画整张表，不为每格默认创建常驻复杂 QWidget |
| 表格外围布局 | 页面 Layout，由 Gen_layout 负责 | 组件不反推页面空白，也不修补页面位置 |

QSS 样式范围可以借助现有 designSystemClass 属性限定到 Z_TableView；表头和滚动条应限制在对应表格上下文内，避免改变无关组件。正式规则需实测，不能仅因为选择器能够输出就认定匹配生效。

表头 padding 不能直接被当成所有正文单元格 padding。正文的精确内容留白、额外行高或特殊文本排版需要验证默认委托与样式的效果，必要时通过公开的委托合同实现。

不得将网页式 line-height、box-shadow 或 CSS 变量直接当作 Qt5 QSS 能力。业务可重写样式，但平台默认实现仍需要合法、可验证的应用链。

## 5. 数据角色、状态与视觉冲突

| 内容 | Qt 基础 | 平台需要约定 |
| --- | --- | --- |
| 文字与编辑值 | DisplayRole / EditRole | 数据类型、显示格式、编辑器，不靠样例字符串猜类型 |
| 图标 | DecorationRole | 资源、尺寸、缩放及主题适配 |
| 复选 | CheckStateRole 与模型 flags | 是否可勾选、三态规则；不与行选择混为一谈 |
| 字体、颜色、对齐 | FontRole / ForegroundRole / BackgroundRole / TextAlignmentRole | 与 QSS、选择态及业务覆盖之间的责任 |
| 特殊单元格 | 自定义委托 | 显示参数、交互事件与生命周期 |

不假定“模型颜色永远覆盖 QSS”或“后加载的一段字符串永远优先”。实际效果涉及样式表范围、选择器、模型角色和绘制实现；必须用目标配置验证。

平台需要确定以下组合的实际效果：正常与悬停、选中与悬停、选中与焦点、禁用与选中、状态色与选中、编辑与业务错误提示。本文不擅自规定尚未批准的颜色优先级。

建议将业务状态通过语义或明确数据角色传入，由统一的样式/委托合同消费；避免平台、业务模型和委托分别维护三份不可追踪的视觉常量。业务仍保留显式覆盖自由，但覆盖后的效果由业务验收。

本轮固定 light-compact，不要求运行时热切换。后续扩展 Profile 时，QSS、模型相关视觉值、委托参数及必要缓存应一致更新。是否支持热切换、如何刷新缓存尚需平台定义，不能因文件有四个版本就宣称已支持热切换。

## 6. 可配置原生能力与公开扩展

| 能力 | 原生基础 | 对外合同应说明 |
| --- | --- | --- |
| 列宽 | Fixed / Interactive / ResizeToContents / Stretch | 参数、尺寸约束、内容测量范围；复杂逐列限制是否额外适配 |
| 行高与换行 | 行高设置、内容适应、wordWrap 与省略规则 | 换行不自动等于行高增长，冲突如何处理 |
| 表头和列结构 | headerData、显示/隐藏、排序指示与列移动 | 逻辑列与视觉顺序如何对应 |
| 选择与编辑 | 选择模式、编辑触发、模型 flags | 选择、勾选、编辑权限相互独立 |
| 排序 | 可排序模型、代理模型或业务事件 | 打开箭头不等于数据排序已实现 |
| 模型与扩展接入 | setModel、委托及信号槽机制 | 所有权、生命周期、模型重置/替换后的配置重应用 |

优先使用继承的 Qt 公开接口，不为每个原生 setter 包装一个同义接口。确需把多项参数组合成稳定合同后，再增加平台公开配置入口；尚未实现的入口不能写成现有方法。

Gen_layout 负责把设计声明转换为实例配置，并在正确时序调用这些接口；Gen_comp 负责接口支持范围、默认行为、验证和组件级实现。业务可以直接调用公开能力、继承或使用提升控件，并独立编写实际业务逻辑。

页面应暴露最终 Qt 对象的公开访问能力。单元格不是固定 QWidget，不为设计样例每一格发布一个对象接口；业务通过模型、列键和记录标识访问数据。

平台原生组件类和专属委托的内部细节不作为稳定外部合同。高自由度来自完整公开能力和明确扩展点，而不是依赖私有子控件名称。

## 7. 平台默认样式与业务局部覆盖

平台发布默认组件 QSS、必要运行配置及资源，Gen_layout 只消费它们并生成必要页面 QSS，不复制整套组件样式实现。

业务可以局部覆盖 QSS、通过原生 API 调整行列、替换委托、继承组件或手改生成文件。推荐将定制独立放置，便于再次导入，但不是限制自由度的强制条件。

平台可重复生成的原始基线与业务接收后手改的副本分开：后者按业务人工维护，不回写平台 Token，也不承诺被下次生成保留。业务需自行保留修改前版本、差异和恢复方法；平台验证不能拿业务手工修正后的效果当作生成器能力。

建议把“平台默认 → 页面实例 → 业务定制”作为维护责任顺序，而不是声称它天然就是 Qt 的最终优先级。覆盖范围、应用方式及实际结果需测试，避免影响其他页面。

公共默认组件的还原由平台与 UCD 验收；被业务覆盖的部分由业务验收。业务定制不自动回写平台 Token，也不要求定制结果仍与原设计稿一致。

### 7.1 公共资源与组件私有资源的发布职责

**已确认采用公共资源与页面资源双轨交付。** 分类、原因、三方职责和生成异常规则完整保存在 [Gen_layout 第 6 节](../../DesignToCode_GenerateLayout/docs/Qt表格设计声明与原生映射.md)。本节只说明组件与 SDK 的责任，不复制页面交付规范，也不扩大本轮表格能力范围。

公共图标、通用图片由平台以 SDK 公共资源发布；组件内部实现专用资源随组件维护，但不自动对业务公开。两者可以使用 Qt QRC 打包，区别在公开合同和维护责任，不在是否使用 QRC。

公共库不应被封闭在某一个控件中。例如搜索图标可能同时被输入框、按钮和工具栏引用，因此它的公开身份应属于公共资源，而不是某个控件的私有子路径。首轮优先在现有 SDK 内明确逻辑目录和清单，不另建独立资源服务。

| 参与方 | 负责内容 | 明确不承担 |
| --- | --- | --- |
| UCD | 公共资产的语义名称、视觉规范、内容与状态变更，设计验收 | Qt 打包、链接和组件私有实现 |
| 平台部 | 资源工程包装、稳定公开标识、构建与初始化说明、SDK 版本和兼容性 | 替每个业务逐张维护页面专用图片 |
| 业务侧开发者 | 消费 SDK 公共资源，集成页面 QRC，通过公开能力替换资源并验收定制 | 依赖平台私有目录、用同名 QRC 路径覆盖 SDK |

统一发布不等于平台独自决定设计内容。UCD 维护设计依据，平台兑现为可引用的工程能力；页面专属资产由 UCD 与业务协作，不必因增加单页插图就等待 SDK 升级，但需要遵守平台的格式与命名约定。

### 7.2 SDK 需要提供什么合同

对本次实际使用的公共资产，SDK 应说明公开资源标识、用途、格式、必要状态、所需版本和使用方式；若打包方式要求显式初始化，也须说明由业务侧开发者何时执行。具体标识及接口须以真实发布内容为准，本文不凭空指定现有方法。

资源内部目录可以调整，公开路径不应随意变化。确需改变公开标识时，应提供迁移说明并记录兼容影响。业务可经公开接口或属性替换为自有资源，但不通过相同 QRC 路径争抢加载顺序；组件私有资源也不因此成为稳定公开 API。

组件的默认图标、状态尺寸与显示规则应与同一 Profile 的 Token、QSS 和运行配置一致。QRC 解决文件可访问，不自动提供主题换色或状态切换；这些能力必须由组件样式或公开实现明确支持并验证。本轮只验证 light-compact，其他组合保留为扩展。

公共资产声明存在但实际缺失时，由平台与 UCD 处理发布或归属问题，Gen_layout 报依赖缺口，不在页面偷偷复制一份替代品。页面专属资源的导出与 QRC 归 Gen_layout，业务图片的运行时获取与权限归业务代码，不转交给组件生成器。

### 7.3 业务构建与样式集成边界

正式页面通过 uic 编译 .ui，业务侧开发者接入 SDK 公开头文件、库和资源；平台应给出与此方式兼容的组件合同。工具预览可以采用独立加载方式，预览成功不能代替业务编译和链接验证。

业务侧开发者统一组织 SDK 组件 QSS、生成的页面 QSS 及业务覆盖样式。生成页面的 .cpp 不替换应用全局样式表，平台组件也不应在内部擅自重设整套应用样式。业务定制的优先级与影响范围按目标 Qt 环境验收，不用职责顺序冒充样式优先级。

## 8. 高级能力与当前缺口

首轮按第 0 节保留浏览与编辑两种模式，共用单层表头、明确列宽和基础单元格，并各自验证最小操作路径。下列能力默认不进入首轮实现，需场景确有需要再调整范围，不因原生类存在就算完成：

| 能力 | 需要解决的问题 |
| --- | --- |
| 多级表头 | 层级、合并、排序命中区域及公开配置；不是普通 QHeaderView 的完整现成功能 |
| 冻结行列 | 滚动与尺寸同步、选择与编辑一致性；不是单一原生开关 |
| 表头全选框 | 作用范围、部分选中及不可选记录；不是默认表头属性 |
| 正文合并 | QTableView 有 setSpan()，但不是合并表头；需处理数据变更及排序关系 |
| 复合单元格 | 多动作、状态与数据合同、委托显示/编辑及性能 |
| 加载、错误、空数据、分页 | 与外围组件的组合合同，不由原生表格自动提供完整业务页面 |

输入语义和结构缺口由 Gen_layout 报告，平台能力和样式缺口在本项目处理。二者不能都通过“页面端临时加代码”被掩盖。

设计侧提供正常、长文本、空值和必要状态样例；不把展示的五条记录作为组件内置业务数据。数据规模、性能阈值和复杂交互要求仍待明确，不在本文编造批准值。

## 9. 组件侧试点验证与后续发布

以下清单只对选定场景声明支持的部件、状态和配置逐项验证，不要求把全部能力一轮做完。未测项写“未验证”，暂缓项不能同时被 SDK 宣称为已支持。本轮没有执行这些测试。

1. 默认表格、表头、正文、选中、禁用及本轮要求的状态有明确样式来源。
2. QSS 无未解析占位符及不支持语法，选择器只影响目标组件范围。
3. 行高、列宽、字体、图标和委托值消费同一 Profile；不出现主题与尺寸来源混用。
4. 模型角色、选择态、QSS 和业务覆盖的组合结果经过实测，没有依赖未验证的优先级假设。
5. 列宽模式、换行、长文本、空值、选择、编辑及排序接入可用。
6. 公开配置在接入、重置或替换模型后仍有明确生效规则和生命周期约定。
7. 复杂单元格没有默认按每格常驻 QWidget 堆积；性能按明确场景验证，未定阈值不宣称达标。
8. 业务可通过公开接口和扩展点定制，未暴露平台私有依赖。
9. SDK 包含声明支持的组件、最终样式及必要资源；公开路径可访问且不与页面 QRC 冲突，组件私有路径未成为业务依赖；未完成的高级能力明确列出。
10. 在组件独立验证通过后，再由 Gen_layout 验证页面转换与业务接入，不互相替代测试。

- 本轮固定 light-compact，并在确定样例后观察两种模式的最小路径；新增其他组合时逐项记录结果，不用单个组合代表四种 Profile 均可用。
- 从固定 Source 重新生成并比较产物；对一个已绑定 Token 做受控修改与恢复，核对预期部件、状态和无关位置。失败要保留，不用手改输出掩盖。

- 生产稳定性还需更广泛业务回归和质量条件，不属于本文件自动保证的结论。本轮复查也不代替 M4 的跨平台重新生成与恢复验证。
