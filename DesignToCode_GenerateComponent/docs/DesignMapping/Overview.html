从设计实例装配 Qt 页面

设计师选择组件、内容、状态与布局；工具按登记规则找到已有 Qt 类，写入页面结构并连接公开接口。组件的颜色、尺寸和材质继续读取现有 Token 产物。

2. 日常开发：按规则读取与装配

阶段动作检查
设计实例组合 Button、IconButton、Checkbox、Input、Select实例身份、属性、Auto Layout 与变量绑定完整
MCP 快照读取主组件 key、实例 ID、属性与布局变量保留原始 JSON 与 SHA-256
规则转换按登记表转换为 UI Contract未知组件、属性、资源和视觉覆写停止输出

业务接入Controller 连接 clicked、valueChanged 等信号业务校验、权限和设备操作由业务代码负责

3. 一个按钮的完整对应关系

QtLab/Button → 设计实例 submitButton → 登记族 Button → commonWidget::Z_PushButton

Label → setText；Type → setType；Size=M → setSize(M)；State=Disabled → setEnabled(false)。运行时的 Hover、Pressed 和键盘焦点由 Qt 事件驱动。

图标使用实例交换属性。登记表把图标主组件身份映射到 QRC 资源键；独立 IconButton 保留 accessibleName 和 Loading。

5. Figma 与 Pixso 的入口

Figma 使用 MCP 实例快照和项目登记表。Pixso 使用 DSM 别名与 D2C+ 解析配置，再转换到同一 UI Contract。DSM 属于 Pixso；Qt 适配层属于本项目。

模型负责调用读取工具、执行规则、运行校验与编译。新的组件类型或视觉能力需要设计与开发明确扩展登记表和组件实现。
