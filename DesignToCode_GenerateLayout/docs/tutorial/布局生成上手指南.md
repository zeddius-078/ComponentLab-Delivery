# 布局生成上手指南

本指南第 1–7 节适用于第一路径 HTML＋DSL。原生 Vue 导出 ZIP/SFC 使用[第二路径说明](../Pixso原生DSM-D2C到Qt第二路径说明.md)，不要求先构造 HTML capture manifest，也不通过第一路径编译器转换。两条路径共用输出规范，不共用输入合同和执行入口。

## 1. 先检查环境

从 GenerateLayout 根目录执行：

```powershell
pwsh -File ../Source/Workspace.ps1 -Action doctor -Target layout `
  -Python '<已有Python3.9/python.exe>' `
  -QtRoot '<Qt5.15 MSVC x64目录>' `
  -VsRoot '<已有VS目录>' `
  -Cmake '<cmake.exe>' `
  -NinjaRoot '<ninja目录>' `
  -Node '<node.exe>' `
  -NodeModules '<包含playwright的node_modules>'
```

该编排脚本位于上一级工作区，单独复制本项目时不能假定它存在。也可以预先设置 `D2C_PYTHON_EXE`、`QT_ROOT`、`VS_ROOT`、`CMAKE_EXE`、`NINJA_ROOT`、`NODE_EXE` 和 `D2C_NODE_MODULES`。工具使用已有环境，不安装新依赖。doctor 的通过不代替实际浏览器适配、SDK 或页面检查。

## 2. 准备 capture manifest

清单把 HTML、DSL、设计文件、根节点、字体、资源和布局证据绑定在一起：

先在 Pixso 客户端打开目标文件，并确认文件 ID、根节点 ID 与本次 HTML 来源一致。采集工具每次写入新的 `output/work` 目录；同一文件在采集期间发生修改时应重新采集整组输入。第一次调用只记录原始 DSL；第二次由 `layout_reference.py` 通过同一只读探针产出布局证据与原始 MCP 记录：

```powershell
py -3.9 -B Source/HtmlDsl/pipeline/capture/capture_mcp.py `
  --tool get_node_dsl --arguments '{"guid":"<根节点ID>"}' `
  --output 'output/work/captures/<批次>/dsl'

py -3.9 -B Source/HtmlDsl/pipeline/capture/layout_reference.py `
  --guid '<根节点ID>' --file-key '<Pixso文件ID>' `
  --dsl 'output/work/captures/<批次>/dsl/canonical.raw.json' `
  --output 'output/work/captures/<批次>/layout'
```

`eval_script` 必须只读。`layout_reference.py` 内部调用既有 `capture_structure.js`（用 `pixso.fileKey` 与 `pixso.getNodeById` 锁定文件及根节点，读取 `layoutMode`、`itemSpacing`、四向 `padding`），把 `design-structure/v1` 快照与 DSL 的 `FRAME` 集合按 GUID 匹配后写入 `layout-reference.json`；原始 01..04 请求/响应保存在同一目录。默认端点 `http://127.0.0.1:3667/mcp`，可用 `--endpoint` 覆盖。本地 stub 测试覆盖正常转换与 fail-closed 路径；真实 Pixso 闭环需采集服务可用后执行，未验证前不宣称闭环通过。

转换口径固定如下；对 DSL `pixTreeNodes[0]` 下的每个 `FRAME` 按 `guid` 匹配快照节点 `id`，包括根节点：

| `layoutReference` 字段 | Pixso 场景快照字段 | 含义 |
| --- | --- | --- |
| `nodes[].id` | `id` | 原设计 GUID；不得从名称推断 |
| `metrics.gap` | `itemSpacing` | 子项间距，设计像素 |
| `metrics.left/top/right/bottom` | `paddingLeft/Top/Right/Bottom` | 四向内边距，设计像素；不是 `x/y` 坐标 |

目标形态是 `{"fileKey":"<Pixso文件ID>","pages":[{"id":"<根节点ID>","nodes":[{"id":"<FRAME GUID>","metrics":{"gap":12,"left":24,"top":24,"right":24,"bottom":24}}]}]}`。示例数字仅表示格式，不得复制为目标文件的值。五项必须是 Pixso 明确返回的有限数字；显式 `0` 保留，缺值不能默认为零。必须检查文件 ID、根节点、FRAME 集合及 GUID 唯一性；`layoutMode` 不受当前适配器支持、返回值不可确定或与 DSL 不同版时停止该正式页面，不通过 HTML/DSL 回填。保存原始 MCP 请求和响应以便追溯。

取得并落地同版 HTML、资源及真实 `layout-reference.json` 后，才创建清单：

```powershell
py -3.9 -B Source/HtmlDsl/pipeline/capture/capture_manifest.py create `
  --output '<采集目录>/capture.json' `
  --html '<采集目录>/page.html' `
  --dsl '<采集目录>/canonical.raw.json' `
  --root-id '<根节点ID>' `
  --file-key '<Pixso文件ID>' `
  --font-family '<字体族>' `
  --layout-reference '<布局证据.json>'

py -3.9 -B Source/HtmlDsl/pipeline/capture/capture_manifest.py verify `
  --manifest '<采集目录>/capture.json' --mode formal
```

正式清单必须包含独立 `layoutReference`。`verify` 会检查每个 DSL `FRAME` 的五项数值及文件哈希；这只验证文件合同，不能证明值确实来自 Pixso。实测当前校验器甚至会让手写 `synthetic-example` 在 `--mode formal` 下返回 PASS，因此不能仅凭该状态授予正式来源资格。浏览器适配还会比较设计证据与 HTML computed style，差异保持 ERROR。清单路径以自身目录为基准。`docs/examples/offline-capture` 只能用于离线技术样例，不能作为目标页面的正式证据。

## 3. 选择 Profile

`-LibraryProfile token-sdk` 使用 GenerateComponent 发布的 SDK。映射目录中的组件身份必须能在 SDK manifest 中找到对应的 canonical ID、Qt 类和公开属性。contract-only Profile 只用于映射或预览测试。

生成前选择模式：`RunPageAudit.ps1` 默认使用 `structure-only`，先生成可校验的静态结构；只有明确传入 `-GenerationMode strict` 时才执行完整外观、属性、Token、布局和 SDK 合同。直接调用 `Generate.ps1` 时必须显式写出 `-GenerationMode strict` 或 `-GenerationMode structure-only`，避免将底层兼容默认值误当成普通生成策略。结构模式只接受完整同版 DSL 和映射目录，保留一对一组件身份与 Qt 类注册校验，跳过实例外观、状态、属性和 Token setter，使用组件默认外观，结果只能写入 `output/work`。

结构模式是固定的低能力路径：调用者不得注入 `variableModeBySetMap`、选择变量模式、补写 DSL 或改用手写 `.ui` 发射器。该模式不求值设计变量，因此变量模式缺失记录为 `NOT_APPLICABLE`；缺失的数值 gap 与四向 padding 固定按 `0` 输出，并在组件 trace 的 `defaultedMetricFields` 中写明。

静态页面不是“失败的 Auto Layout”。当 `FRAME` 的 `stackMode=NONE` 或缺失，且每个直接子节点均明确给出父级相对 `left/top/width/height`，结构模式使用 `absolute-geometry`：生成嵌套 `QWidget` 并把几何写入 `.ui`，原始 `childNode` 顺序作为叠放顺序保留，记录到 `trace.staticLayouts`。不补 Spacer、不按坐标排序、不推测缺失约束。子节点缺任一几何值时返回 `STATIC_GEOMETRY_REQUIRED`。有 `HORIZONTAL`、`VERTICAL`、`GRID`、`FORM` 的容器仍使用对应 Qt Layout；Grid/Form 行列/跨度、组件身份或目标类缺失仍是错误。普通非组件 Frame 使用 Qt 原生 `QWidget` 承载，contract-only 组件库无须重复声明该框架类；未知组件实例不因此获得回退。`strict` 不启用此静态策略。

```powershell
pwsh -File Source/HtmlDsl/Generate.ps1 `
  -GenerationMode structure-only `
  -RawDsl '<同版canonical.raw.json>' `
  -MappingDirectory '<组件库映射目录>' `
  -Font '<已有字体文件>' `
  -OutputDirectory 'output/work/structure-only/<批次>/<页面>' `
  -LibraryProfile '<组件库Profile>'
```

`structure-only` 不需要 HTML、浏览器适配或 `layoutReference`，因为它消费的是已采集的静态 DSL 几何；其中缺失的数值间距与内边距会被明确标记为默认零，而不是冒充设计端实测值。它不能替代正式 `capture manifest`，也不能宣称视觉、交互、Token 或消费者编译通过。

组件实例默认仍作为叶节点。需要把指定实例的内部子层写入 `.ui` 时，使用显式白名单：

```powershell
pwsh -File Source/HtmlDsl/Generate.ps1 `
  -GenerationMode structure-only `
  -ExpandInstance '2:28481' `
  -RawDsl '<普通 isDetachInstance=false 的同版 DSL>' `
  -MappingDirectory '<组件库映射目录>' `
  -Font '<已有字体文件>' `
  -OutputDirectory 'output/work/structure-only/<批次>/<页面>'
```

`-ExpandComponent 'ComponentLab/TableView'` 可按组件名称展开全部匹配实例。展开使用普通 DSL 的组件身份和 `pixComponentTreeDslNodes` 母版 `childNode`；分离 DSL（`isDetachInstance=true`）只能作为结构采集证据，不能单独生成，身份字段为空时明确返回 `DETACHED_DSL_REQUIRES_BASE_IDENTITY`。展开失败时保留外层组件类，并在生成 trace 的 `warnings` 中记录原因；不会自动扩大展开范围，也不会改变默认模式。

## 4. 正式生成页面

```powershell
pwsh -File Source/HtmlDsl/Generate.ps1 `
  -CaptureManifest '<capture.json>' `
  -MappingDirectory '<映射目录>' `
  -Font '<字体文件>' `
  -Batch '<批次>' `
  -Page '<页面名>' `
  -LibraryProfile token-sdk
```

生成器按以下顺序工作：验证清单、浏览器测量、解析组件、转换布局、输出页面文件、执行 `uic` 检查。已有页面目录拒绝覆盖。

需要固定顺序自动执行、失败继续并汇总结果时，使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Source/HtmlDsl/RunPageAudit.ps1 `
  -Url 'https://pixso.cn/app/design/<fileKey>?item-id=<rootId>'
```

该入口默认只执行到 structure-only 与 `uic`，strict、正式验收会记录为 `NOT_RUN`，不会创建 delivery。需要正式合同验收时显式追加 `-GenerationMode strict`；普通步骤失败只记录并继续，缺少前置输入时下游标记 `SKIP`，工具完整性或输出路径安全失败时停止受影响分支。结果写入 `output/work/audit/<批次>/result.json` 和 `REPORT.md`，原始日志写入 `output/logs/audit/<批次>/run.log`。默认完成即返回 0；需要 CI 失败码时加 `-FailOnError`。

## 5. 检查页面包

```text
output/delivery/<批次>/<页面>/
├─ form/<页面>.ui
├─ include/<页面>.h
├─ src/<页面>.cpp
└─ view/res/
   ├─ qss/<页面>.qss
   └─ <页面>.qrc
```

`.ui` 保存结构和布局；`.cpp` 初始化页面和运行时属性；页面 `.qss` 保存页面级视觉规则；公共组件样式和 Token 来自 SDK。

## 6. 结构预览

结构预览使用结构 DSL 和独立初始样式，适合确认节点层级、身份和固定画布位置：

```powershell
py -3.9 -B Source/HtmlDsl/PreviewStructure.py `
  --input 'output/work/captures/<批次>/structure.json' `
  --style docs/examples/styles/initial-light.json `
  --font docs/examples/resources/HarmonyOS_Sans_SC_Regular.ttf `
  --qt-root '<已有Qt目录>' `
  --output 'output/work/preview/<批次>/page'
```

预览中的未知节点用 QWidget 表达，输出可供结构检查。它不提供完整业务组件行为，预览结果不能代替正式组件映射。

## 7. 验证与定位

```powershell
py -3.9 -B docs/validation/check_delivery.py --formal-batch '<批次>'
pwsh -File docs/validation/formal/Verify-RelocatedConsumer.ps1 `
  -Batch '<批次>' -SdkRoot '<SDK目录>'
```

| 阶段 | 检查内容 |
| --- | --- |
| capture | 文件路径、哈希、根节点、资源和布局证据 |
| adapt | HTML 渲染、字体和受支持布局测量 |
| generate | 组件、布局和页面文件 |
| uic | `.ui` XML 解析 |
| consumer | 头文件、库、QRC 和 CMake |
| runtime | 页面启动和初始状态 |
| visual | 设计版本与运行结果 |

缺少输入、哈希不匹配、组件未登记、布局定位缺失或 SDK 不完整时，记录具体节点和阶段并停止后续阶段。日志写入 `output/logs`，临时数据写入 `output/work`。
