# 布局生成上手指南

## 1. 先检查环境

从 GenerateLayout 根目录执行：

```powershell
pwsh -File Source/Workspace.ps1 -Action doctor `
  -Python '<已有Python3.9/python.exe>' `
  -QtRoot '<Qt5.15 MSVC x64目录>' `
  -VsRoot '<已有VS目录>' `
  -Cmake '<cmake.exe>' `
  -NinjaRoot '<ninja目录>' `
  -Node '<node.exe>' `
  -NodeModules '<包含playwright的node_modules>'
```

也可以预先设置 `D2C_PYTHON_EXE`、`QT_ROOT`、`VS_ROOT`、`CMAKE_EXE`、`NINJA_ROOT`、`NODE_EXE` 和 `D2C_NODE_MODULES`。工具使用已有环境，不安装新依赖。

## 2. 准备 capture manifest

清单把 HTML、DSL、设计文件、根节点、字体、资源和布局证据绑定在一起：

```powershell
py -3.9 -B Source/HtmlDsl/pipeline/capture/capture_manifest.py create `
  --output '<采集目录>/capture.json' `
  --html '<采集目录>/page.html' `
  --dsl '<采集目录>/canonical.raw.json' `
  --root-id '<根节点ID>' `
  --file-key '<Pixso文件ID>' `
  --font-family '<字体族>' `
  --layout-reference '<布局证据.json>'

py -3.9 -B Source/HtmlDsl/pipeline/capture/capture_manifest.py verify `
  --manifest '<采集目录>/capture.json' --mode formal
```

正式清单必须包含独立 `layoutReference`。该文件来自设计节点的布局属性读取；浏览器测量结果不能反向替代它。清单路径以自身目录为基准。

## 3. 选择 Profile

`-LibraryProfile token-sdk` 使用 GenerateComponent 发布的 SDK。映射目录中的组件身份必须能在 SDK manifest 中找到对应的 canonical ID、Qt 类和公开属性。contract-only Profile 只用于映射或预览测试。

## 4. 正式生成页面

```powershell
pwsh -File Source/HtmlDsl/Generate.ps1 `
  -CaptureManifest '<capture.json>' `
  -MappingDirectory '<映射目录>' `
  -Font '<字体文件>' `
  -Batch '<批次>' `
  -Page '<页面名>' `
  -LibraryProfile token-sdk
```

生成器按以下顺序工作：验证清单、浏览器测量、解析组件、转换布局、输出页面文件、执行 `uic` 检查。已有页面目录拒绝覆盖。

## 5. 检查页面包

```text
output/delivery/<批次>/<页面>/
├─ form/<页面>.ui
├─ include/<页面>.h
├─ src/<页面>.cpp
└─ view/res/
   ├─ qss/<页面>.qss
   └─ <页面>.qrc
```

`.ui` 保存结构和布局；`.cpp` 初始化页面和运行时属性；页面 `.qss` 保存页面级视觉规则；公共组件样式和 Token 来自 SDK。

## 6. 结构预览

结构预览使用结构 DSL 和独立初始样式，适合确认节点层级、身份和固定画布位置：

```powershell
py -3.9 -B Source/HtmlDsl/PreviewStructure.py `
  --input 'output/work/captures/<批次>/structure.json' `
  --style docs/examples/styles/initial-light.json `
  --font docs/examples/resources/HarmonyOS_Sans_SC_Regular.ttf `
  --qt-root '<已有Qt目录>' `
  --output 'output/work/preview/<批次>/page'
```

预览中的未知节点用 QWidget 表达，输出可供结构检查。它不提供完整业务组件行为，预览结果不能代替正式组件映射。

## 7. 验证与定位

```powershell
py -3.9 -B docs/validation/check_delivery.py --formal-batch '<批次>'
pwsh -File docs/validation/formal/Verify-RelocatedConsumer.ps1 `
  -Batch '<批次>' -SdkRoot '<SDK目录>'
```

| 阶段 | 检查内容 |
| --- | --- |
| capture | 文件路径、哈希、根节点、资源和布局证据 |
| adapt | HTML 渲染、字体和受支持布局测量 |
| generate | 组件、布局和页面文件 |
| uic | `.ui` XML 解析 |
| consumer | 头文件、库、QRC 和 CMake |
| runtime | 页面启动和初始状态 |
| visual | 设计版本与运行结果 |

缺少输入、哈希不匹配、组件未登记、布局定位缺失或 SDK 不完整时，记录具体节点和阶段并停止后续阶段。日志写入 `output/logs`，临时数据写入 `output/work`。
