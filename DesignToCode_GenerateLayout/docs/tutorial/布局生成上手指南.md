# 布局生成上手指南

本项目把同一设计版本的 Pixso HTML 和 DSL 合并为 Qt 页面。HTML 提供浏览器实测布局，DSL 提供节点层级、组件身份、实例属性和 Token 引用。项目只维护 HTML + DSL 路线。

## 固定环境

先读取工作区 AGENTS.md；不安装或升级 Python、Qt、编译器、Node 与依赖。缺少工具时先报告。源码只保存工具实现；固定输入在 docs，所有执行输出在 build。

## 校验组件 SDK

```powershell
pwsh -File Source/Verify-GeneratedComponentSDK.ps1
```

构建默认直接读取同级 `DesignToCode_GenerateComponent/build/sdk`。外部工作区可通过 `GENERATED_COMPONENT_SDK_ROOT` 指向同一权威发布目录。本项目不复制 SDK。

## 组装采集清单

采集工具保存 MCP 原始响应，D2C 工具保存 HTML 和本地资源；两者需要通过清单组装为同一版输入。清单路径以自身目录为基准，避免依赖当前 PowerShell 工作目录。

```powershell
python -B Source/HtmlDsl/pipeline/capture/capture_manifest.py create `
  --output '<采集目录>/capture.json' `
  --html '<采集目录>/page.html' `
  --dsl '<采集目录>/canonical.raw.json' `
  --root-id '<设计根节点ID>' `
  --file-key '<Pixso文件ID>' `
  --font-family '<字体族>' `
  --resource '<临时URL>=<本地资源路径>' `
  --layout-reference '<Pixso布局证据.json>'
python -B Source/HtmlDsl/pipeline/capture/capture_manifest.py verify `
  --manifest '<采集目录>/capture.json' `
  --mode formal
```

正式清单必须包含 `layoutReference`。该文件应来自 Pixso 的独立布局属性读取，不能由浏览器测量结果反向生成。

## 正式生成

```powershell
pwsh -File Source/HtmlDsl/Generate.ps1 `
  -CaptureManifest '<capture.json>' `
  -MappingDirectory '<Compact映射目录>' `
  -Font '<字体文件>' `
  -Batch '<批次>' `
  -Page '<页面工程名>'
```

输出进入 `build/delivery/<批次>/<页面>`。正式页面包含 `.ui/.h/.cpp/.qss/.qrc`；QRC 注册页面 QSS，页面需要本地资源时追加资源条目。

## 验证

```powershell
python -B docs/validation/check_delivery.py --formal-batch '<批次>'
pwsh -File docs/validation/formal/Verify-RelocatedConsumer.ps1 -Batch '<批次>' -SdkRoot '<SDK目录>'
```

预览也必须显式传入结果页和复核页清单：

```powershell
pwsh -File Source/HtmlDsl/Generate.ps1 `
  -Preview `
  -CaptureManifest docs/fixtures/layout/html-dsl/result-page/capture.json `
  -ReviewCaptureManifest docs/fixtures/layout/html-dsl/holdout-19-45/capture.json `
  -MappingDirectory docs/fixtures/layout/mapping `
  -Font docs/examples/resources/HarmonyOS_Sans_SC_Regular.ttf `
  -LibraryProfile token-sdk
```

预览清单只用于回归夹具，不能替代正式清单。未映射组件会终止生成，并返回节点与缺失映射；组件实现应在 GenerateComponent 补齐后重新发布 SDK。

`Source/HtmlDsl`、`docs/examples/Qt` 和 `docs/validation` 共同构成布局生成工具链。工具链输出页面文件包与演示程序，不发布组件库或第二套 SDK。布局结构矩阵位于 `docs/validation/layout/test_shape_matrix.py`，用于验证纵向、横向、嵌套和重复生成。

## 多库映射测试

两种入口均支持 -LibraryProfile。默认 token-sdk 消费现有 SDK；analysis-system 读取独立组件 JSON。只修改 JSON 的 classPrefix 就可切换目标类名前缀及自动头文件名，不修改原系统。

不需要完整 HTML 采集链的专项映射测试，可使用 [组件库切换规范](../designRules/library-profiles.md) 的 canonical 夹具命令。它只检验解析/命名，不替代 capture 校验与正式页面验收。analysis-system 为 contract-only/planned，正式模式会拒绝；没有目标组件实现时，不做编译运行完成承诺。

每次执行先验证清单哈希，旧夹具不得因历史通过而跳过。导航栏 Token 消费契约问题仍挂起；失败按所属层报告。历史阶段结果统一存 docs/archive。
