# 布局文件输出要求

## 页面交付单元

每个页面批次输出一个可被业务工程继续加工的页面单元：

```text
<Page>/
├─ form/<Page>.ui
├─ include/<Page>.h
├─ src/<Page>.cpp
└─ view/res/
   ├─ qss/<Page>.qss
   └─ <Page>.qrc
```

`.ui` 保存结构、objectName、布局和可序列化属性。`.h` 声明页面类与公开访问器。`.cpp` 完成 `setupUi`、运行时属性和页面信号连接。页面 `.qss` 保存页面专属样式。`.qrc` 注册页面样式和页面自有资源。

公共组件的 `.h/.cpp/QSS/Token` 由 GenerateComponent SDK 提供，页面生成器只引用公开接口。业务模型、数据请求和业务动作由业务 Qt 工程维护。

## 稳定性要求

同一版本输入重复生成时，页面目录、类名、objectName、布局关系和资源引用保持一致。页面包不得依赖生成过程中的临时文件、报告或当前 PowerShell 工作目录。

## 验证顺序

1. 按输入路径核对来源与哈希：第一路径使用 capture manifest、DSL、HTML、layoutReference；第二路径使用原始导出清单、SFC/CSS/资源、映射和旁置生成记录，不伪造同批 DSL 或浏览器证据。
2. 核对组件身份、Profile 与公开 API 合同。第二路径 export-first 允许已声明的属性/内容/视觉差异继续生成候选，但必须保留未应用记录，不能改称完整合同。
3. `.ui` 可由 Qt 5.15.2 `uic` 解析。
4. 页面能在独立消费者工程中编译并链接已发布 SDK。
5. 运行时组件状态、页面 QSS 和资源可加载。
6. 视觉比对与设计版本一致。

每一步单独记录结果。结构通过、编译通过和视觉通过属于不同结论。

第二路径的 `STAGED` 仅表示候选写入及哈希校验完成。真实页面验证必须绑定同一生成记录、SDK 和页面文件；该记录放在页面目录外，不作为运行依赖。当前实现状态和命令以[第二路径说明](../Pixso原生DSM-D2C到Qt第二路径说明.md)为准，不能借第一路径的正式交付通过状态替代。
