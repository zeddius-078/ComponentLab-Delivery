# 布局生成执行与验收规则

## 当前结论

正式页面交付使用 `wide-light` Profile；预览映射默认使用 `standard-light`。`Compact`、`Comfortable` 等值只属于组件或布局 Density，不属于 Profile。当前有效 Profile 仅为：

- `standard-light`
- `standard-dark`
- `wide-light`
- `wide-dark`

正式产物是由 uic 消费的 `.ui/.h/.cpp/.qss/.qrc` 页面文件包。生成器只写本项目的 `build/delivery/<批次>/<页面>`，不直接写业务仓库，不复制组件 SDK 实现。

## 事实源与边界

| 内容 | 当前事实源 | 边界 |
| --- | --- | --- |
| 组件身份、类型、公开类 | GenerateComponent 发布的 `design-component-catalog.json` | Asset 与 LayoutHelper 不进入 QWidget Factory |
| 组件外观与 Profile | GeneratedComponentSDK Token/QSS 资源 | 页面不得复制组件内部样式 |
| 组件/布局映射 | `docs/fixtures/layout/mapping/` | 未登记值必须失败，不能静默回退 |
| 页面输入 | 通过 `capture_manifest.py verify` 的同源清单 | HTML、DSL、资源与根节点必须属于同一批输入 |
| 页面产物 | `build/delivery` 与包外 `generation-record.json` | 追溯记录不成为运行依赖 |

公共资产使用 `icon.*`、`image.*`、`model.*` 稳定 ID。它们可由布局展示和调用，但不生成组件类。`model.*` 当前只表示二维大型插图；不得推导 3D、交互命中或实时仿真能力。

## 正式生成

正式模式要求：

1. `CaptureManifest`、字体文件、MappingDirectory 均存在；
2. MappingDirectory 中 `component-mapping.json.profile` 必须为 `wide-light`；
3. `Batch`、`Page` 只允许字母、数字、下划线和连字符；
4. 目标页面目录不存在，禁止覆盖已有交付；
5. 输入清单通过 formal 模式校验；
6. `v2_ui_compiler` 已构建。

入口：

```powershell
pwsh -File Source/HtmlDsl/Generate.ps1 `
  -CaptureManifest '<capture.json>' `
  -MappingDirectory '<mapping目录>' `
  -Font '<字体文件>' `
  -Batch '<批次>' `
  -Page '<页面工程名>'
```

预览必须显式加 `-Preview`，并同时提供结果页与复核页清单。预览结果不得作为正式交付替代物。

## 验收规则

| 检查层 | 通过条件 |
| --- | --- |
| 输入 | 清单、根节点、HTML/DSL/资源哈希与模式校验通过 |
| Profile | 只出现四个现行名称；正式交付为 `wide-light` |
| Density | 作为组件/布局属性独立校验，不改变 Profile |
| 身份 | 每个公开组件、LayoutHelper、Asset 都能在 SDK 目录中解析 |
| 结构 | `.ui` 可解析，对象名唯一，布局方向、行列、跨度、Form 角色有效 |
| 资源 | 公共语义 ID 能由 SDK Catalog 解析；未知 ID 明确失败 |
| 构建 | 独立消费者可通过 uic、编译、链接和离线运行检查 |
| 行为 | 禁用、输入、确认、返回和必要信号路径通过测试 |
| 视觉 | 使用实际字体与资源完成截图复核；自动测试通过不等于视觉签核 |

建议验证入口：

```powershell
python -B docs/validation/component/check_mapping.py
python -B docs/validation/layout/test_shape_matrix.py
pwsh -File docs/examples/Qt/V2/Build.ps1 -Test
pwsh -File docs/examples/Qt/V2/Verify.ps1
python -B docs/validation/check_delivery.py
```

只有实际执行成功的命令才能写入验收结论。旧 Profile、旧 Pixso 输入、历史生成目录和旧报告不得作为当前通过证据。
