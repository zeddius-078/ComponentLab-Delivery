# 布局转换器通用化规范

## 1. 目标

本规范定义 DesignToCode_GenerateLayout 的布局转换边界：

~~~text
设计侧布局语义
    -> layout-mapping.json
    -> LayoutConverter
    -> Qt 运行时布局对象
    -> .ui XML
    -> uic / 业务 Qt 工程
~~~

转换器统一返回 QLayout*，并根据映射结果创建具体布局：

| 设计语义 | Qt 类型 | 专属定位信息 |
| --- | --- | --- |
| HORIZONTAL | QHBoxLayout | 子项顺序、间距、对齐 |
| VERTICAL | QVBoxLayout | 子项顺序、间距、对齐 |
| GRID | QGridLayout | 行、列、行跨度、列跨度 |
| FORM | QFormLayout | 行号、LabelRole、FieldRole、SpanningRole |

QLayout* 只负责提供通用的运行时承载类型。布局语义仍由设计输入、映射合同和各布局分派逻辑共同决定。

| 文件 | 作用 |

| Source/HtmlDsl/pipeline/engines/layout_converter/LayoutConverter.cpp | 创建布局、校验字段、加入子项、写出布局轨迹 |

| docs/validation/layout/test_shape_matrix.py | 生成 .ui 并检查布局类、定位属性和重复生成稳定性 |

## 3. 类型分派

转换器按 layout-mapping.json 的 modes 分派，不把未知布局降级为盒式布局：

~~~text
HORIZONTAL -> QHBoxLayout
VERTICAL   -> QVBoxLayout
GRID       -> QGridLayout
FORM       -> QFormLayout
~~~

Box 布局继续使用已有的顺序、主轴对齐、交叉轴对齐、间距、内边距和尺寸策略。Grid/Form 分别使用自己的 Qt API：

~~~cpp
QBoxLayout::addWidget(widget, stretch, alignment);
QGridLayout::addWidget(widget, row, column, rowSpan, columnSpan, alignment);
QFormLayout::setWidget(row, role, widget);
~~~

因此，通用返回类型不意味着所有布局都使用同一个插入方法。

## 4. Grid 映射规则

容器的 autoLayout.stackMode 设置为 GRID。子节点在 layoutItem 中提供：

~~~json
{
  "gridRow": 0,
  "gridColumn": 1,
  "gridRowSpan": 1,
  "gridColumnSpan": 2
}
~~~

规则：

1. gridRow 和 gridColumn 必须存在，且为大于等于 0 的整数。
2. gridRowSpan 和 gridColumnSpan 缺省为 1，显式值必须为大于等于 1 的整数。
3. 跨度覆盖的每一个网格单元都会登记；重复占用返回 GRID_CELL_OVERLAP。
4. gridRowGap、gridColumnGap 缺省使用通用间距；明确提供时分别生效。
5. gridRowStretch、gridColumnStretch 使用非负整数数组，分别写入 setRowStretch() 和 setColumnStretch()。
6. 单元格对齐使用 gridHorizontalAlign、gridVerticalAlign，值域沿用 flex-start、center、flex-end。

.ui 输出使用 Qt Designer 的定位属性：

~~~xml
<layout class="QGridLayout" name="gridLayout">
  <item row="0" column="0">
    <widget class="QLabel" name="titleLabel"/>
  </item>
  <item row="1" column="0" colspan="2">
    <widget class="QLineEdit" name="valueEdit"/>
  </item>
</layout>
~~~

## 5. Form 映射规则

容器的 autoLayout.stackMode 设置为 FORM。子节点在 layoutItem 中提供：

~~~json
{
  "formRow": 0,
  "formRole": "label"
}
~~~

formRole 的值域和 Qt 角色对应如下：

| 设计值 | Qt 角色 | .ui 列 |
| --- | --- | --- |
| label | QFormLayout::LabelRole | column="0" |
| field | QFormLayout::FieldRole | column="1" |
| spanning | QFormLayout::SpanningRole | column="0" colspan="2" |

Form 规则：

1. formRow 必须是大于等于 0 的整数。
2. 同一行同一角色只能出现一次。
3. SpanningRole 表示跨越表单的 Label/Field 两列，不使用 Grid 的任意跨行跨列规则。
4. formFieldGrowthPolicy 支持 fieldsStayAtSizeHint、expandingFieldsGrow、allNonFixedFieldsGrow。
5. formRowWrapPolicy 支持 dontWrapRows、wrapLongRows、wrapAllRows。
6. formColumnGap、formRowGap 明确设置时分别写入 Qt 表单布局。

.ui 输出保持 Qt Designer 的表单行列表达：

~~~xml
<layout class="QFormLayout" name="formLayout">
  <property name="fieldGrowthPolicy">
    <enum>QFormLayout::AllNonFixedFieldsGrow</enum>
  </property>
  <item row="0" column="0">
    <widget class="QLabel" name="nameLabel"/>
  </item>
  <item row="0" column="1">
    <widget class="QLineEdit" name="nameEdit"/>
  </item>
</layout>
~~~

## 6. 公共字段与专属字段

| 字段类别 | Box | Grid | Form |
| --- | --- | --- | --- |
| 四边内边距 | autoLayoutPadding* | 同左 | 同左 |
| 通用间距 | autoLayoutItemSpacing | 缺省间距 | 缺省间距 |
| 尺寸策略 | Fixed/Hug/Fill | layoutWidthSizing / layoutHeightSizing，缺省 Fixed | 同左 |
| 子项顺序 | reverse-childNode | 仅影响稳定处理顺序，位置由行列决定 | 仅影响稳定处理顺序，角色由契约决定 |
| 对齐 | 主轴/交叉轴 | 单元格水平/垂直 | 标签、表单整体 |
| 定位 | 无 | 行、列、跨度 | 行、角色 |

布局定位字段不能由几何坐标推断。设计侧未提供必需字段时，正式生成返回明确错误，不用 left/top 填补布局语义。

## 7. .ui 与运行时验证

生成器按以下顺序验证：

1. LayoutConverter 创建 Qt 运行时布局并写出 trace.layouts[].items。
2. UiCompiler 根据实际布局类型输出 .ui。
3. Qt 5.15.2 uic 解析 .ui。
4. 布局测试检查运行时类型、位置、跨度、角色、间距和拉伸。
5. 结构矩阵测试检查 .ui 类名、item 属性和重复生成字节一致。

验收矩阵：

| 场景 | 验收内容 |
| --- | --- |
| Box 回归 | HBox/VBox 顺序、间距、内边距、尺寸策略和对齐保持原行为 |
| Grid 定位 | 非连续行列、跨行/跨列、行列拉伸可重建 |
| Form 角色 | LabelRole、FieldRole、SpanningRole 可重建 |
| 混合嵌套 | 父布局中保留子布局类型和定位关系 |
| 异常输入 | 缺定位、非法跨度、重复格子、重复角色、未知类型明确失败 |

命令：

~~~powershell
$env:QT_ROOT = 'D:\QT\5.15.2\msvc2019_64'
pwsh -File docs/examples/Qt/V2/Build.ps1 -CompileOnly
python -B docs/validation/layout/test_shape_matrix.py
~~~

## 8. 当前支持边界

当前实现已登记并测试 QHBoxLayout、QVBoxLayout、QGridLayout 和 QFormLayout。这表示转换器和 .ui 生成链路具备对应能力，不表示任意 Pixso 页面都自动拥有完整定位数据。

设计侧仍需按本规范输出布局语义。未提供 Grid 行列或 Form 行角色的页面会在生成阶段失败，并返回可定位的错误码。绝对定位、未登记节点类型和未知布局模式继续保持失败关闭。
