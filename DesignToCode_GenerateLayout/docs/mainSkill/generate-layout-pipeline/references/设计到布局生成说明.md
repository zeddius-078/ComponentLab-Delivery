# 设计到布局生成说明

本说明仅针对第一路径 HTML＋DSL。原生 Vue 导出件使用[第二路径说明](../../../Pixso原生DSM-D2C到Qt第二路径说明.md)，不继承本页的浏览器适配、ComponentFactory 或 capture manifest 输入要求。两条路径共用页面文件规范，不能据此混用实现和验收结果。

## 1. 设计数据的两种作用

HTML 记录浏览器环境中的实际布局和文字测量。DSL 记录节点层级、设计身份、属性、状态和 Token 引用。HTML 与 DSL 通过 capture manifest 绑定为同一版本输入。

```text
HTML + DSL + layoutReference
             -> capture manifest
             -> adapter
             -> layout/component compiler
             -> Qt page package
```

## 2. 组件身份

设计节点的 `componentRef`、`variantProperties` 和实例属性进入组件转换器。转换器查询 GenerateComponent SDK 的 manifest，得到 canonical ID、Qt 类、公开属性和值域。页面生成器消费现有 `Z_*` 组件，组件源码和公共 QSS 继续由 GenerateComponent 管理。

设计名、节点 ID、objectName 和开发类名分别保存。设计名用于阅读，节点 ID 用于追溯，objectName 用于页面访问，开发类名来自 SDK 合同。

## 3. 布局语义

页面节点先进入布局模型，再转换为 Qt 类型：

| 设计语义 | Qt 类型 | 关键数据 |
| --- | --- | --- |
| 横向 | `QHBoxLayout` | 顺序、间距、对齐 |
| 纵向 | `QVBoxLayout` | 顺序、间距、对齐 |
| 网格 | `QGridLayout` | row、column、rowSpan、columnSpan |
| 表单 | `QFormLayout` | row、LabelRole、FieldRole、SpanningRole |

几何坐标用于 HTML 测量和结构核对。Grid/Form 的定位字段来自设计合同，不能从几何坐标猜测。

## 4. 页面文件职责

| 文件 | 生成内容 |
| --- | --- |
| `.ui` | 页面层级、布局、objectName 和可序列化 Qt 属性 |
| `.h` | 页面类、对象访问器和声明 |
| `.cpp` | `setupUi`、运行时属性和信号连接 |
| 页面 `.qss` | 页面容器和页面专属样式 |
| `.qrc` | 页面 QSS 与页面资源 |

公共组件的 Token、QSS、绘制和工厂由 SDK 提供。页面初始化只调用公开 API。

## 5. 组件初始化

SDK 页面按以下顺序初始化：

```text
应用主题 -> setupUi -> 注册页面 QRC -> ComponentFactory -> 页面 QSS
```

`.ui` 能表达的结构和属性写入 XML。颜色、字体和状态样式由 SDK Token/QSS 消费。需要运行时 API 的属性写入页面 `.cpp`。业务数据和动作由业务工程连接。

## 6. 生成结果

页面批次包含：

```text
<Page>/form/<Page>.ui
<Page>/include/<Page>.h
<Page>/src/<Page>.cpp
<Page>/view/res/qss/<Page>.qss
<Page>/view/res/<Page>.qrc
```

页面目录还应携带生成清单或其包外报告，用于记录输入版本、Profile、SDK manifest 和生成时间。页面运行不依赖报告。

## 7. 质量检查

先检查输入哈希和组件合同，再检查结构、uic、消费者编译、运行状态和视觉结果。同一输入重复生成时，页面结构、名称、布局定位和资源引用应保持一致。

缺少组件合同时回到 GenerateComponent。缺少 Grid/Form 定位时回到设计数据。输入、工具、SDK 和目标页面应分别记录来源。
