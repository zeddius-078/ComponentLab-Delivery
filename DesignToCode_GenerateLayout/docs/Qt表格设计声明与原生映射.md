# 表格设计读取、Qt 页面生成与业务工程接入

更新日期：2026-10-03。

**本文件属于 Gen_layout，回答“怎样读取设计表格，将其转换成 Qt 页面交付件，并由业务接入”。它不定义平台表格的内部样式实现。**

本文保存已确认的九类设计声明与交付边界。设计属性导出格式、具体转换字段和完整接口仍待实现，不代表生成器已经支持全部规则。

配套文档：[Gen_comp：Qt 表格组件样式、Token 与应用合同](../../DesignToCode_GenerateComponent/docs/Qt表格设计声明与原生映射.md)。两份文件按职责互相引用，不是主本与副本，不再要求全文同步或哈希相同。保留现有文件路径，避免原链接失效。

## 0. 本轮试点验证合同

**当前目标是让试验范围、输入、过程和证据可控，不承诺创新探索立即形成稳定产品质量。** 本文是 C++ Qt 表格专题的试点验证合同，不是通用表格生成器的生产就绪声明，也不代表其他平台已经完成。

### 0.1 与规划的关系

参照 [试点规划 v4.6](../../DesignToCode_GenerateComponent/docs/Orders-Design-System-协同排期/README.md)：设计声明对应 M2-14；生成与交付规则对应 M3-04、M3-14；真实业务接入对应 M3-16。组件实现和样式验证由 Gen_comp 承担。本专题不另建一套排期，不代替 M4 的跨平台复验。

该规划仍标记 2026-08-28，旧日期和“生成文件不得手改”等表述未随本轮更新。本文按 2026-10-02 已确认决定允许业务自行导入和手改，不以旧规定撤销授权；总规划的版本同步仍待处理，不宣称文档已完全一致。

### 0.2 两种模式、同一个表格族

| 本轮对象 | 最小验证内容 | 本轮不自动扩展为 |
| --- | --- | --- |
| 数据浏览模式 | 单层表头、明确列宽、基础内容、选择和一条声明的排序路径；真实数据由业务接入 | 通用查询系统、远程排序平台或完整分页框架 |
| 可编辑模式 | 在同一表格族中验证一类基础单元格的编辑、只读限制及修改结果回传；校验/提交由独立业务代码接入 | 通用表单引擎、完整校验系统或复杂事务提交 |

两种模式都保留为目标，不因浏览模式跑通就把整个表格族标为完成。具体列、编辑类型和必要状态在选定样例时固定；不能把文中的全部原生能力都变成本轮必做项。

多级表头、冻结、表头全选、合并单元格、复杂行操作和复合单元格默认暂缓。若真实试点离不开其中某项，先调整范围和验证安排，再实现；不由工具自行扩大任务。

### 0.3 开始试验前填清范围

以下信息在本节维护一次，Gen_comp 引用同一范围，不再建立重复场景清单。

| 范围项 | 当前状态 |
| --- | --- |
| 真实业务项目、页面和代码位置 | 待选；现有 Demo 不自动算真实业务试点 |
| 设计输入版本、表格身份、列与状态 | 待固定；九类声明中不适用项需说明 |
| 浏览与编辑的具体操作路径 | 待固定；包含各自预期结果 |
| SDK、生成器、Token、Profile 与测试环境 | Profile 已确定为 light-compact（亮色紧凑）；SDK、生成器、Token 版本与测试环境待记录，结论不得外推到未测组合 |
| 样例数据规模、长文本/空值、实际体验判定方式 | 待确定；不编造性能阈值或统一像素容差 |

这些项未明确时，可以做隔离技术探针，但不能报告真实业务场景已经验证。换设计版本、SDK、Profile 或数据规模后，原结果只能作为旧条件下的证据。

### 0.4 创新结果怎样记录

每次试验在既有独立生成记录中保留：问题或假设、固定输入、预期结果、实际观察、日志/截图/差异、处理及复查结果。业务导入与回退证据由业务侧提供给记录，不赋予工具写项目权限。

结论只使用“未验证”“已观察”“已复查”等明确描述：一次运行是已观察；相同条件重放并完成相应检查才能称已复查。两者都不等于稳定质量、任意页面适用或生产就绪。

失败也可以形成有价值的探索结论，但必须保留失败现象和原因，不能把“完成了一次试验”写成“完成了功能”。必要设计属性缺失、静默丢失、越权写入和绝对定位兜底仍不允许，不因创新任务而放宽。

## 1. 工具、组件与业务的边界

| 参与方 | 在本链路中负责 | 不负责 |
| --- | --- | --- |
| UCD | 设计结构、列语义、尺寸及交互声明，补齐 Token，设计验收 | 编写业务代码、猜测平台内部实现 |
| 平台部 | 维护 Gen_layout 和组件 SDK，明确可读取字段、转换规则及公开接口 | 替业务逐页生成、维护或发布界面 |
| 业务部 | 使用工具生成文件，自行导入工程，接入数据、权限与流程，维护定制 | 替工具猜设计属性或修复基础转换错误 |

Gen_layout 消费已发布的组件 SDK。表格以 QTableView 原生能力为基线，项目组件身份使用 SDK 已发布的 commonWidget::Z_TableView，不在页面生成器里复制另一份表格实现。

工具只写独立输出目录，没有业务项目写入权限。业务侧按目标相对路径插入、替换文件。允许独立扩展，也允许手改生成文件；再次导入前由业务自行比较与合并，工具不承诺保留手改。

工具输出的原始基线保留用于重新生成对照；业务导入后手改的副本按业务人工维护文件管理。人工改动不回写平台事实源，不计入工具可重复生成的能力；文件清单区分这两种归属，防止下次覆盖时误认为无差异。

“页面接入骨架”只包含初始化、组件访问、配置应用和信号槽接入入口。数据请求、权限判断、业务校验及实际操作实现不进入生成骨架。

## 2. 读取、转换、接入的目标流程

```text
Pixso 表格组件与明确设计属性
→ 读取九类设计声明，核对类型、来源和完整性
→ 查询已发布的 Qt 表格能力与配置合同
→ 转换为页面结构、实例配置、必要页面 QSS
→ 输出 .ui / .h / .cpp / .qss，独立保存生成记录
→ 业务自行导入工程，加载页面与已发布 SDK
→ 绑定业务模型和事件，验证集成结果
```

这里的“读取”包含设计输入读取，以及生成 Qt XML 的加载验证；不表示运行中的业务应用需要读取 Pixso、MCP 或设计追溯文件。

每一步都要区分输入有效、转换成功、页面可加载、业务可接入。不能用其中一个结果代替全部。

## 3. 九类必需设计声明

以下九类声明是本文件维护的完整输入清单。字段不适用时明确标为“不使用”；不能从截图、设计样例值或图层位置猜测。具体机器字段名称与 Pixso 导出格式尚未冻结。

| 类别 | 设计侧必须说明 | Gen_layout 读取与转换要求 |
| --- | --- | --- |
| 1. 表格身份 | 稳定语义名称，如 recipeTable | 生成可读的对象名及类型明确的页面访问入口 |
| 2. 列身份与顺序 | 稳定列键、显示标题、顺序、初始可见性 | 校验列键唯一，生成逻辑列配置，不靠标题猜字段 |
| 3. 列宽规则 | 固定、可拖动、内容适应或填充；必要的初始值和约束 | 转为 SDK 支持的尺寸模式，检查所需参数是否齐全 |
| 4. 表头与行尺寸 | 表头高度、正文行高、固定或内容适应策略 | 读取属性或 Token；将尺寸交给原生表格公开配置 |
| 5. 单元格类型 | 文本、数字、日期、图标、复选或复合内容 | 查询组件能力；未知类型不能悄悄退化成文本 |
| 6. 文本规则 | 对齐、换行、省略、完整内容提示、数值和日期格式 | 传递显示合同，不通过一条样例推断通用格式 |
| 7. 选择与编辑 | 按行/单元格选择、单选/多选、可编辑列和触发方式 | 生成支持的声明与接入点，不替业务决定最终权限 |
| 8. 排序与操作 | 可排序列、初始排序、操作标识、触发方式及状态 | 生成配置和事件入口，不生成真实业务处理 |
| 9. 视觉与状态 | 字体、颜色、边线、选中、禁用等规则及 Token | 对接 Gen_comp 的样式与状态合同，不重复实现单元格绘制 |

### 3.1 逻辑身份与展示信息分开

列键 recipeName 表达“配方名称”，表头可以更换文案或语言。设计师不需要提前知道数据库字段；业务负责数据字段映射。

列重排、隐藏、改标题不能改变逻辑列身份。真实记录的稳定标识由业务提供，排序后的行号不能作为长期记录身份。

页面类与文件采用大驼峰，控件与布局采用小驼峰语义名。设计节点 ID 不作为公开名称，名称映射进入独立生成记录；再次生成有历史记录时应复用已确认工程名。

### 3.2 可读取才算完整输入

设计声明应落实为可读取的组件属性、规范化结构或双方约定的结构化标注。画板旁的说明文字不能自动视为工具已经获得的参数。

必须核对实际 MCP/导出内容。工具没有读到时，要区分设计未声明与采集适配遗漏，不能统一归责设计侧。

## 4. 布局与尺寸转换规则

| 设计声明 | Qt 原生映射基线 | 生成器必须检查 |
| --- | --- | --- |
| 固定列宽 | QHeaderView::Fixed | 明确宽度或 Token |
| 可拖动列宽 | QHeaderView::Interactive | 初始宽度及允许范围；特殊逐列限制是否有平台适配 |
| 按内容决定 | QHeaderView::ResizeToContents | 数据变化影响尺寸；不能保证等于设计样例 |
| 填充可用空间 | QHeaderView::Stretch | 不当作任意比例分配，也不覆盖所有设计工具的 Fill 语义 |

列宽声明还要包含窄窗口处理、横向滚动及是否允许列移动。文本换行与行高变化必须分开声明：只开启 wordWrap 不保证单元格会自动增高。

表格外围布局读取设计属性，水平、垂直关系分别使用 QHBoxLayout、QVBoxLayout；明确二维页面排列才使用 QGridLayout。表格内部行列由 Qt 表格管理，不展开成页面 GridLayout 或多个 Label。

固定留白来自设计的 padding、gap 等属性，不允许从画面空白、截图或坐标差填写。Spacer 必须来自 Pixso 显式组件映射，不能自行增加以凑齐表格位置。

无职责的空节点和包装层不保留；有视觉、事件、尺寸约束或组件职责的容器保留并记录理由。不得为还原每一个设计包装层而制造 QWidget。

禁止对子控件使用绝对定位，也禁止用 move()/setGeometry() 绕过页面布局。原生表格管理内部单元格位置不等于生成页面绝对定位。无法可靠转换时报告问题，不做绝对定位兜底。

内容适应是明确声明的 Qt 运行行为，不等于生成器猜测尺寸。

## 5. Token、组件能力与错误处理

| 输入情况 | 处理 | 责任与记录 |
| --- | --- | --- |
| 有有效 Token 绑定且 SDK 可消费 | 按平台合同解析、映射并消费 | 记录引用关系；交付只保留运行所需值与接口 |
| 属性明确、符合规范，但未绑定 Token | 允许按原值生成 | 独立记录缺口，由设计侧补全后重新生成 |
| 有 Token 但无法解析、类型不符或与配置冲突 | 报错，不静默改用猜测值 | 区分源定义、SDK 合同与转换器问题 |
| 设计声明完整但平台不支持该能力 | 报组件能力缺口，停止相关页面正式交付 | Gen_comp 处理，不在 Gen_layout 临时另造实现 |
| 必要设计属性缺失或含义不明 | 报设计待确认项，停止相关页面正式交付 | UCD 补全；不得从截图反推 |
| 合同完整且能力支持，但转换错误 | 报工具缺陷 | 平台修复，不要求业务手改兜底 |

没有 Token 的明确值仍允许生成并交业务试用，但不计作 Token 完整接入，也不能由工具擅自创建新 Token。补全日志至少记录对象、属性、当前值、来源、责任方和后续验证要求。

“可以生成”“可以探索试用”“设计标准化完成”“试点目标验证完成”是不同结论。按试点规划，纳入首批标准化范围的稳定视觉属性仍须由设计侧补齐 Token 并复查；未补齐不报告该项标准化通过。范围外缺口可保留，不要求为一次小样补齐整套表格库，也不建立复杂条件放行流程。

样式能力及原生 API 的具体实现由配套 Gen_comp 文档负责，本文件只定义读取、校验和传递。

## 6. 业务交付件与独立生成记录

每个页面必须生成以下四个文件，文件名以实际页面名称替换 PageName：

```text
form/PageName.ui
include/PageName.h
src/PageName.cpp
view/res/qss/PageName.qss
```

| 文件 | 表格相关内容 | 不应包含 |
| --- | --- | --- |
| .ui | 页面布局、SDK 表格实例、对象名及可表达的声明属性 | 拆散模拟的表头、固定业务行数据、设计追溯 ID |
| .h | 表格等页面对象的类型明确访问入口与必要接入声明 | SDK 私有成员依赖、设计节点编号接口 |
| .cpp | 页面初始化、实例配置应用与接入骨架 | 数据请求、权限判断、业务校验及手写业务流程 |
| .qss | 页面范围内需要的最终样式；无专属规则时保留说明 | 未解析占位符、重复复制整套 SDK 样式 |

运行必需的表格配置可进入骨架；确需独立配置文件时按已约定的 config/ 路径交付，不强制为表格额外创建一份 JSON。图标和 QRC 按实际依赖生成，不使用本机绝对资源路径。

生成追溯单独保存为 generation-record.json，位于交付包之外。它保存设计链接、节点 ID、工程名映射、版本、诊断、Token 缺口和接口变化，不作为业务应用运行依赖。

稳定列键、组件类名、公开头文件、运行资源路径属于必要的工程信息，不是需要移走的设计追溯信息。

### 6.1 资源采用双轨交付，不在公共库和页面 QRC 之间二选一

**已确认：公共资源由平台统一发布，页面专属资源随页面交付。** 以下是已确认的页面与组件通用接入约定，也适用于本表格专题；不意味着本轮额外建设一套完整资产管理平台。

QRC 是 Qt 的资源打包与引用机制，不是责任归属。公共资源也可以通过 QRC 随组件 SDK 集成，页面资源则通过自己的 QRC 随页面导入。因此，“使用 QRC”并不等于“与平台无关”，“平台提供资源”也不等于“所有图片都必须由平台逐张维护”。

公共资源库与组件库可以随同一 SDK 发布，但应在逻辑上分开。搜索图标可能同时用于输入框、按钮和工具栏，不能因为最先用于按钮，就把它变成只能经由按钮组件访问的私有资源。

| 资源类别 | 典型内容 | 内容与工程责任 | 交付方式 |
| --- | --- | --- | --- |
| 公共设计资源 | 搜索、关闭、警告图标，通用空状态插图 | UCD 维护视觉、语义和内容；平台维护工程包装与发布 | 引用 SDK 已发布公共路径，不随每页复制 |
| 组件私有资源 | 某组件内部指示图形或实现专用图片 | 平台维护实现，视觉规则与 UCD 对齐 | 随组件内部资源发布，不自动成为业务公开接口 |
| 页面专属静态资源 | 特定工艺引导图、单页说明插图 | UCD 与业务侧共同确定内容；业务侧开发者集成和维护 | 随页面导出实际文件及独立 QRC |
| 动态业务图片 | 用户上传图片、运行中的设备截图 | 业务侧管理获取、权限、存储及生命周期 | 由业务运行时代码加载，不默认编入 QRC |

判断依据是复用范围和维护责任，不是文件格式。同为 SVG，可以是公共图标，也可以是页面专用示意图；同为 PNG，也不代表都应嵌入应用。工具不能仅凭外观相似就合并两份资产。

### 6.2 三方怎样分工，为什么这样分

**UCD 负责设计内容，不只提供文件。** 公共资产需要有明确用途、语义名称、视觉规格、必要状态和版本变化说明。页面专属素材也需明确尺寸、裁切及显示规则，避免开发者从截图猜使用方式。

**平台部负责公共能力的工程兑现。** 平台将批准的公共资产组织为 SDK 可引用资源，提供稳定公开路径、构建或初始化说明以及兼容规则。组件内部使用哪些私有资源由平台负责，不要求业务了解组件内部目录。

**业务侧开发者负责页面接入与业务定制。** 业务侧使用 Gen_layout，自行导入页面文件及页面 QRC，连接 SDK 资源，执行构建和验收。页面新增一张专属插图不应强制等待平台发布；但仍须遵守平台约定的资源格式和命名边界。

这样划分既避免每个业务复制一套公共图标，也避免平台成为每张业务图片的维护人。公共资源的内容决定由 UCD 与使用方协作，工程发布由平台负责；不能把“统一发布”误解为“平台独自决定所有设计内容”。

首轮只整理实际试点用到的资源，优先利用现有 SDK 内的资源目录和清单。不新增独立资源服务、仓库或全公司资产治理流程作为试点前置条件。

### 6.3 Gen_layout 的资源读取、输出和异常规则

| 输入情况 | 工具应做什么 | 不允许做什么 |
| --- | --- | --- |
| 已映射到公共资源 | 读取 SDK 公共资源标识，生成运行所需引用 | 复制公共文件进每个页面包 |
| 已明确为页面专属资源 | 导出资源文件和页面 QRC，输出可移植引用 | 引用开发者本机绝对路径或临时下载地址 |
| 声明为公共资源，但 SDK 中缺失 | 记录公共依赖缺口，由平台与 UCD 补齐或明确调整归属 | 静默改为页面资源以掩盖缺失 |
| 未明确资源归属或读取失败 | 区分设计声明不足、采集失败与映射缺失，记录待处理项 | 按图片相似度擅自归并，或假装导出成功 |
| 业务希望替换资源 | 通过公开属性、接口或业务自有路径接入 | 用与 SDK 相同的 QRC 路径覆盖平台资源 |

影响页面必要显示的资源缺失时，不把该页面标为正式交付完成；可以保留已有输出用于问题复查。工具只操作独立输出目录，不自动向业务工程复制资产、修改构建配置或替换 SDK。

资源的设计链接、设计节点、原始下载地址、归属判断和映射过程进入交付包之外的 generation-record.json。页面 .ui、QSS 或骨架只保留必要的运行资源引用，不依赖追溯日志才能启动。

### 6.4 资源路径与替换边界

公共资源与页面资源需要不同命名空间，避免多个页面导入后出现同名冲突。以下仅为建议格式，**不是已经核验存在的 SDK 路径**；正式前缀、文件大小写和公开标识须以平台实际发布合同为准。

```text
:/platform/icons/search.svg
:/platform/images/empty-state.svg
:/pages/RecipeSettingView/images/process-guide.png
```

公开路径是消费者依赖的合同，资源内部存放目录不必成为合同。平台调整内部文件组织时应尽量保留公开路径；确需变更时说明影响与迁移方式。页面使用独立前缀，业务替换通过明确的公开入口实现，不依赖重复路径的加载先后顺序。

Gen_layout 输出页面专属 QRC 与其引用的真实文件；只有 XML 清单、缺少资源文件，不算完整交付。公共资源不重复打包，但独立生成记录需要记清所依赖的 SDK 版本与公开资源标识，便于业务侧开发者检查构建条件。

### 6.5 怎样验证资源分工已经落实

验证应覆盖公共路径可用、页面文件齐全、QRC 已参与业务构建、无同名路径冲突、无临时地址，以及替换资源后无关页面不受影响。检查必须在实际业务接入方式下完成，不能只以工具预览能够显示图片为依据。

本轮使用 light-compact。资源尺寸、状态与样式按该标准核对；其他主题和密度作为后续扩展，不宣称自动换色、自动换图或四种 Profile 均已验证。SVG 是否能按预期加载、染色或缩放也须以目标 Qt 环境实测，不根据扩展名推定能力。

## 7. 业务导入、Qt 加载与数据接入

以下为交付使用规则，不代表当前工程已经逐项实现。

1. 业务侧开发者检查所需 SDK 版本及公开合同，自行将文件添加或替换到目标路径，配置公开头文件、库依赖及页面 QRC 构建。
2. 正式业务交付采用 uic 编译 .ui，通过生成的页面骨架初始化 SDK 组件；ui_*.h 是构建中间文件，不是额外手工维护的交付件。不复制平台组件实现，也不静默退回普通 QWidget。
3. 页面加载后，按列键应用结构及尺寸配置；依赖模型列数的设置必须在模型接入后生效，不能只在空表初始化时执行一次。
4. 业务绑定自己的数据模型和事件处理。设计稿中的五行仅为样例，不默认生成五条生产记录。
5. 模型重置、切换或列变化后，应按照公开合同重新核对配置；不能把旧列序号绑定到新的字段。
6. 业务验证数据展示、操作、排序及业务定制，再自行构建发布。工具不进入业务仓库执行这些修改。

工具预览与正式业务加载分开。预览可以使用 QUiLoader，但须通过平台公开注册方式创建自定义组件；预览成功不能替代 uic 编译、链接 SDK 和业务初始化验证。

**样式集成由业务侧开发者负责。** 平台提供组件最终 QSS，工具提供页面最终 QSS，业务侧统一组织其应用并接入自己的覆盖规则。页面生成的 .cpp 不擅自替换 QApplication 的全局样式表，页面专属选择器应限制在页面范围内。

平台默认、页面实例和业务覆盖是维护责任划分，不保证“最后拼接的一段 QSS 必然优先”。实际结果仍需检查选择器、应用范围和 Qt 样式行为。工具不越权修改业务工程的全局样式入口。

本轮统一使用 light-compact，页面布局、页面 QSS、SDK 样式及运行配置必须一致。后续可扩展其他组合，但当前不要求四套 .ui、自动主题切换或运行时热切换。

“全部暴露”针对最终页面对象及其公开能力。应能访问表格、表头、模型和选择等原生公开能力；不能给每个动态单元格制造一个固定 QWidget 接口，也不能穿透平台组件私有子结构。

排序需要有能力的模型、代理模型或业务处理。出现排序箭头并不证明排序逻辑有效。选中、勾选和权限也是不同概念，不能相互代替。

业务可独立覆盖样式、调整布局、继承、提升控件及手改生成文件。生成基线验收与业务定制验收分开；后者不强求与原设计稿一致。

## 8. 首轮范围、缺口与验收

首轮使用第 0 节明确的浏览、编辑两种模式和选定输入。单层表头、列宽、基础单元格、选择与排序是共用基础；编辑模式必须另外验证最小编辑接入路径。高级需求仍要读取和识别，不能因为暂不支持而丢弃。

多级表头、冻结行列、表头全选框、正文合并单元格、复合单元格、分页和加载/错误等状态需要逐项查平台能力。正文 setSpan() 不等于多级表头；扩展实现由 Gen_comp 定义。

以下为选定范围内的逐项验证要求，未实际执行的项保持“未验证”。首轮 Profile 固定为 light-compact，不要求覆盖全部列类型或尺寸模式，不得声称未测组合已通过。

1. 九类设计声明可读取；缺省与“不使用”有明确区别，不猜属性。
2. 列键、对象名唯一且可读；改表头文案不无故改变调用身份。
3. .ui/.h/.cpp/.qss 齐全，所需 SDK 类型和配置可解析。
4. .ui 经 uic 编译、链接 SDK 并初始化成功，列结构与表头正确，不靠样例假数据掩盖空模型问题。
5. 宽度策略、窄窗口、长文本、空值和行高行为符合声明，没有绝对定位或补位置 Spacer。
6. 未支持能力和输入冲突得到诊断；已允许的未绑定 Token 值进入设计补全记录。
7. 设计来源只在独立记录中；业务接入不需要 Pixso 节点 ID 或采集缓存。
8. 数据、权限、排序处理与操作事件可以由独立业务代码接入。
9. 分别记录生成、加载、交互、视觉四类结果，不以启动成功代替全部。
10. 导入替换过程由业务控制，不覆盖用户项目或承诺自动保留业务手改。
11. 公共资源只引用已发布路径；页面资源文件及 QRC 齐全，构建后可加载，无路径冲突或临时地址依赖。
12. 业务侧统一集成 QSS，生成页面不替换应用全局样式；样式、布局、资源和运行配置共同遵循 light-compact。

### 最小复查与回退证据

- 固定同一输入和工具版本重新生成，比较四类交付文件；日志时间等非运行元数据单独说明，不用来掩盖产物差异。
- 选择一个已绑定 Token 做受控修改，再恢复；验证预期消费位置变化并恢复，无关位置不应被改变。失败则保留证据并继续处理，不填写“稳定”。
- 业务记录导入前版本、导入文件及手改差异，能说明如何恢复；工具不代替业务执行覆盖或回退。
- 记录一次真实加载、浏览操作和最小编辑操作，保留必要截图及失败案例。这只能证明选定条件下的结果，不替代 M4 全范围复验。
