# 离线使用与发布

## 使用端

使用完整离线包，并在包外创建独立工作目录。包内应包含自研工具、组件 SDK、Python、Node、Playwright、匹配浏览器、Qt/VC 运行库、资源、许可和版本清单。

```bat
Run.cmd doctor --work "E:\页面工作"
Run.cmd generate --work "E:\页面工作" --capture "D:\工具包\examples\capture\capture.json" --batch firstRun --page samplePage
Run.cmd gallery --work "E:\页面工作"
```

生成结果写入工作目录，包本身保持只读。HTML、DSL、资源和 capture manifest 使用同一版本。示例输入标记为 `synthetic-example`，它用于验证技术链路。

## 开发端打包

先完成：

```powershell
pwsh -File Source/Workspace.ps1 -Action doctor
pwsh -File Source/Workspace.ps1 -Action build -Target all
pwsh -File Source/Workspace.ps1 -Action verify
pwsh -File Source/Workspace.ps1 -Action package -ReleaseInputs '<批准的输入清单.json>'
```

发布清单记录 Python、Node、Node modules、浏览器、Qt、VC 运行库、资源和许可依据。许可确认来自实际负责人，Agent 不代填批准字段。

## 交付判定

| 阶段 | 证明内容 |
| --- | --- |
| `doctor` | 工具路径和依赖文件存在 |
| `build` | 当前源码已生成并构建工具、SDK 和展示程序 |
| `verify` | 开发机回归通过 |
| 离线运行 | 包内路径、资源和运行库可用 |
| 视觉验收 | 指定页面和组件完成独立视觉核对 |

各阶段单独记录结果。示例通过、开发机通过和新机器通过分别记载。
