# 三项目上手指南

## 阅读顺序

1. 阅读[三项目总体架构](../designRules/architecture/项目总体架构.md)，确认任务属于组件生成、组件展示还是页面生成。
2. 进入目标项目，阅读项目根目录 `README.md`。
3. 执行项目前先读取该项目 `docs/mainSkill/*/SKILL.md`。
4. 按所属项目的验证命令检查结果，不使用另一个项目的源码代替依赖。

## 固定环境与模式选择

先读取工作区 AGENTS.md。不得自主安装或升级已匹配环境；缺依赖或版本冲突先报告。文档更新和目标库命名测试不要求重发 SDK。导航栏 Token 消费问题仍挂起，发布流程是操作入口，不代表当前全链已经通过。

## 常用流程

### 修改组件或 Token

```powershell
cd G:\ComponentLab-Delivery\DesignToCode_GenerateComponent
pwsh -File Source/Publish-ComponentSDK.ps1
pwsh -File docs/validation/SDKConsumerTest/Build.ps1
python -B Source/CheckProject.py
```

发布成功后，`build/sdk` 成为工作区唯一权威组件 SDK。ComponentLab 和 GenerateLayout 分别运行校验脚本，并直接引用该目录。

### 检查组件展示

```powershell
cd G:\ComponentLab-Delivery\ComponentLab
pwsh -File Source/Verify-GeneratedComponentSDK.ps1
pwsh -File Source/delivery/tools/Build.ps1
python -B Source/delivery/tools/CheckProject.py
```

### 生成 Qt 页面

```powershell
cd G:\ComponentLab-Delivery\DesignToCode_GenerateLayout
pwsh -File Source/Verify-GeneratedComponentSDK.ps1
pwsh -File Source/HtmlDsl/Generate.ps1 -CaptureManifest '<capture.json>' -MappingDirectory '<映射目录>' -Font '<字体文件>' -Batch '<批次>' -Page '<页面名>'
python -B docs/validation/check_delivery.py --formal-batch '<批次>'
```

## 完成判定

- 组件能力只由 GenerateComponent 发布。
- ComponentLab 和 GenerateLayout 校验并直接引用唯一权威 SDK，不保存 SDK 副本，也不引用兄弟项目源码。
- GenerateLayout 发布布局生成工具链和页面包（ui/h/cpp/qss/qrc），不发布第二套 SDK。
- GenerateLayout 只维护 HTML + DSL 路线。
- 构建产物进入所属项目的 `build`，说明文档进入所属项目的 `docs`。
- 实际执行的构建、测试和检查结果写入所属项目的 `build/reports`。

## 只测试目标库命名

在 GenerateLayout 按 [组件库配置规范](../../DesignToCode_GenerateLayout/docs/designRules/library-profiles.md) 使用 -LibraryProfile analysis-system；一处 classPrefix 改变目标类与自动头文件名。此库仅声明类，不能用于正式可运行交付。默认 token-sdk 保持不变。

历史阶段记录和过去验收统一归档 docs/archive；build/reports 只保存当次可再生报告。
