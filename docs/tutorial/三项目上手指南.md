# 三项目上手指南

## 1. 检查环境

在工作区根目录执行：

```powershell
pwsh -File Source/Workspace.ps1 -Action doctor
```

入口使用已经安装的工具。当前环境需要 Python 3.9、Qt 5.15.2、MSVC、CMake、Ninja、Node、Playwright 及匹配浏览器。工具路径可通过命令参数或进程环境变量传入。

## 2. 构建顺序

```powershell
pwsh -File Source/Workspace.ps1 -Action build -Target all
```

工作区按以下顺序处理：

1. GenerateComponent 生成并发布 `build/sdk`。
2. GenerateLayout 编译布局工具并运行其测试。
3. ComponentLab 校验 SDK，构建展示程序。
4. 根工具记录构建收据。

如果 SDK 不存在，先执行完整构建。SDK 由 GenerateComponent 生成，消费项目读取其公开包。

## 3. 回归验证

```powershell
pwsh -File Source/Workspace.ps1 -Action verify
```

验证包括 Token/组件检查、SDK 消费测试、布局结构测试、页面生成测试、ComponentLab 测试和工作区文档/边界检查。

## 4. 三个项目的直接入口

| 项目 | 入口 | 作用 |
| --- | --- | --- |
| GenerateComponent | `Source/Publish-ComponentSDK.ps1` | 生成和发布 SDK |
| ComponentLab | `Source/delivery/tools/Build.ps1` | 构建组件展示程序 |
| GenerateLayout | `Source/Build.ps1` | 构建布局工具和测试 |

完整的组件、布局和验证步骤分别见三个项目的 `docs/`。

## 5. 清理

普通清理只处理 `output/work` 和 `output/logs`。`build/sdk`、`build/tools` 和 `build/.state` 属于受控运行资产，删除前必须确认能够重新发布并验证。

## 6. 离线包

离线包通过 `Source/Workspace.ps1 -Action package -ReleaseInputs <清单>` 生成。使用端运行包内的 `Run.cmd`，不调用开发仓库的 Source，也不安装系统依赖。具体命令见[离线交付](离线交付.md)。
