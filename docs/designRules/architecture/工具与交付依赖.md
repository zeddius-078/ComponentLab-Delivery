## 执行边界

脚本只检查并使用已经安装的工具。依赖路径通过当前进程参数或环境变量传入，常用变量为 `QT_ROOT`、`VS_ROOT`、`CMAKE_EXE`、`NINJA_ROOT`、`NODE_EXE`、`D2C_NODE_MODULES` 和 `D2C_PYTHON_EXE`。

构建前由 `doctor` 检查版本、路径、SDK 清单和运行库。编译与暂存写入 `output/work`，通过对应验收后才受控更新 `build`；交付批次写入 `output/delivery`，日志写入 `output/logs`。第三方许可证随交付包保存。

## GitHub 源码与运行资产领取

源码仓库保存三个项目的维护输入、完整自研工具源码、构建与打包入口、映射、固定测试输入和文档。`build` 中的二进制及第三方运行文件不进入 Git 源码历史；目录 README 是例外。源码下载或 clone 不等于领取完整运行包。

正式使用端必须领取通过验收的 Release 附件，包内需要同时具备布局工具、组件 SDK、展示程序、Python、Node、Playwright、Chromium、Qt/VC 运行库、字体、资源及许可材料。不能用依赖清单代替实际运行文件，也不能要求使用端临时安装或补包。

## 依赖关系

```text
Pixso HTML + DSL
        -> GenerateLayout 工具
        -> Qt 页面文件
        -> Qt 5.15.2 / GeneratedComponentSDK
        -> 业务 Qt 工程
```

`GeneratedComponentSDK` 是 GenerateComponent 的发布物。GenerateLayout 读取 SDK 的头文件、库、QSS、资源和 manifest；页面生成器不复制组件实现。ComponentLab 使用同一 SDK 展示组件状态。
